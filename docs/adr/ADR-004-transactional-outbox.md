# ADR-004: Транзакционный Outbox

## Статус
Принято

## Контекст
События не должны теряться, если транзакция БД зафиксирована, но публикация в брокер
провалилась, равно как агрегат не должен откатываться из-за временной недоступности
брокера. Наивный подход «public after commit» создаёт именно эту проблему dual-write.

## Решение
Принять **паттерн Transactional Outbox**.

Для любого мутирующего use case, порождающего доменное событие, обновление агрегата и
строка outbox пишутся в *одной* локальной транзакции БД:

```
BEGIN TRANSACTION
  UPDATE shipment ...
  INSERT INTO outbox_event (event_type, payload, status='PENDING', next_attempt_at=now())
COMMIT
```

Затем запланированный **publisher** (`OutboxPublisher`):

1. Выбирает подлежащие строки через `SELECT ... FOR UPDATE SKIP LOCKED`, чтобы
   одновременно работающие инстансы publisher'а никогда не публиковали двойную копию.
2. Публикует каждое событие в RabbitMQ (publish-подтверждения).
3. Только в случае успеха помечает строку `PUBLISHED`.

При сбое публикации событие повторяется с экспоненциальным backoff до `MAX_RETRIES`,
после чего помечается `FAILED` для разбора технологом/оператором. Метрика
`outbox_events.pending` измеряет накопленный backlog, а счётчик сбоев публикации —
надёжность.

## Альтернативы
- **Скатывать бизнес-транзакцию при сбое публикации** (публикация внутри транзакции):
  связывает быструю локальную БД с более медленным удалённым брокером и снижает
  доступность; отклонено.
- **2-phase commit (XA) между БД и RabbitMQ**: добавляет сложность и хрупок;
  отклонено.
- **CDC (например, Debezium)** из журнала транзакций: мощно, но требует дополнительной
  инфраструктуры; здесь проще и достаточно outbox.

## Последствия
- Нет рассинхронизации между состоянием БД и опубликованными событиями.
- Publisher идемпотентен, опираясь на строку БД как источник истины; повторная
  доставка брокером уже обрабатывается дедупликацией consumer'а.
- Джоба очистки может вычищать старые строки `PUBLISHED` (сейчас метрика
  `countPending` даёт видимость; архивация/очистка оставлены как будущее улучшение).
- Компромисс ограничен: никакого внешнего CDC, только реляционная таблица outbox.
