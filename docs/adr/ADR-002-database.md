# ADR-002: База данных (PostgreSQL + Flyway)

## Статус
Принято

## Контекст
Сервис должен хранить отправления долговечно, обеспечивать уникальность трек-номеров,
поддержку пагинации/фильтрации по статусу, конкурентный доступ на основе
оптимистичной блокировки, outbox и ключи идемпотентности. Изменения схемы должны быть
версионируемы и отслеживаемы.

## Решение
Использовать **PostgreSQL 16** с **Flyway** как единственным источником истины схемы.

- `ddl-auto=validate`, чтобы Hibernate при старте сверял свой маппинг со схемой,
  управляемой Flyway; `create`/`update` запрещены во всех профилях.
- Одна миграция `V1__create_shipments.sql` создаёт таблицы `shipments`,
  `outbox_events`, `idempotency_keys` и последовательность `tracking_number_seq`.
- Ограничения: PK во всех таблицах; `UNIQUE(tracking_number)`; check-ограничения для
  enum статуса и типа доставки; положительные вес/габариты.
- Индексы добавлены только там, где служат реальным запросам:
  - `idx_shipments_status_created (status, created_at DESC)` для фильтруемого списка.
  - `idx_outbox_due (status, next_attempt_at) WHERE status IN ('PENDING','FAILED')`
    для запроса выборки outbox.
  - `idx_idempotency_expires (expires_at)` для джобы очистки.
  - Поиск по трек-номеру использует уникальный индекс.
- Метки времени — `TIMESTAMPTZ`, а `version BIGINT` обеспечивает оптимистичную
  блокировку.

## Альтернативы
- **MySQL/MariaDB**: функционально достаточно, но Postgres-конструкции `INSERT ... ON CONFLICT`,
  `FOR UPDATE SKIP LOCKED` и частичные индексы лучше всего подходят под наши
  потребности в outbox/идемпотентности.
- **MongoDB**: отклонён, сервис сильно согласован и реляционен.
- **Liquibase**: столь же допустим; Flyway выбран за предсказуемые упорядоченные
  SQL-миграции и широкое распространение.

## Последствия
- Эволюция схемы явна и воспроизводима во всех окружениях.
- Hibernate падает быстро при рассинхронизации маппинга (validate).
- Уникальный индекс трек-номера гарантирует отсутствие дубликатов даже при конкуренции.
- Пути с «тяжёлыми» `update` остаются дешёвыми (индексированный PK, отсутствие N+1 по дизайну).
